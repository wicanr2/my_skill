# 模型成本分工 — 貴的模型留給判斷，粗活交給便宜的

用高階（貴）模型的 session 裡，最容易浪費的方式是拿它做「不吃判斷力的機械工作」：
對碼盤點、逐斷言核實、grep 比對、檔案清單巡查。這些工作便宜模型做得一樣好。

> 來源：用旗艦模型 review 一個多主題原始碼分析知識庫。fan-out 派了多個「專家/學生 review sub-agent」
> 全部繼承旗艦模型，被使用者兩度手動停掉：「太貴」「用貴的 model 分析爛程式價值不高」。
> 事後看，那些 agent 做的事（抽斷言→grep 原始碼→回報不符）確實不需要旗艦判斷力。

## 硬規則

- **不要預設 fan-out review/核實 sub-agent**，尤其在高階模型 session——sub-agent 預設繼承主迴圈模型，
  一次派四個等於燒四倍。要派就先講成本、或明確指定 `model: haiku` / `model: sonnet`。
- **依工作性質切模型**：判斷、取捨、寫作、架構理解 → 高階模型；機械核實、盤點、比對 → 便宜模型
  （主迴圈 `/model` 切換，或 sub-agent 帶 model 參數）。拿不準就先用 inline 的少量 grep 抽驗代替 fan-out。
- **筆記/分析寫到「夠用」就停**：深挖的價值集中在架構、機制、柵欄（Chesterton's Fence）與跨主題連結；
  檔案級長尾投報比低，登進 PLAN/worklist 待辦即可，之後「用到哪、修到哪」被動維護。
- **review 文件時抽「可驗證斷言」回原始碼 grep**，比重讀全文便宜且有效——文件斷言會過期，
  code 才是唯一真相（配 [`63-truth-in-code-not-stale-markers`](63-truth-in-code-not-stale-markers.md)）。

## Why

- token 費用與價值不成正比的工作，換便宜模型後品質不變、成本降一個量級。
- 「全部交給旗艦」和「全部省著用」都是懶惰的預設；成本分工本身就是一個要動腦的架構決策。
- 使用者對成本的敏感度是真實約束——被喊停一次就該把這條寫成規則，不是下次再犯。
