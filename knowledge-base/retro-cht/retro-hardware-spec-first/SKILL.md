# 老機器的硬體規格：先查規格，不要反推

> 來源：《Dungeon Master》DOS 版重製（`~/cht/dungeon_master/`），2026-08 定案。
> 配 `rulebook/62`（靜態反追溯源）、`retro-game-remake` 使用。

**核心結論**：反組譯適合回答「**這個遊戲**怎麼做」，
不適合回答「**這台機器**的晶片跑多快」。後者是查得到的既有事實。

---

## 1. 判別：這個問題該查還是該反推

| 問題形狀 | 該用什麼 | 為什麼 |
|---|---|---|
| 取樣率、CPU／音效晶片時脈、PIT 分頻基準、VDP 掃描行數、調色盤位元寬 | **查公開規格**（機器的硬體 wiki、晶片 datasheet） | 全機通用的既有事實，與這一款遊戲無關 |
| 這款遊戲把哪個值寫進那個暫存器、表在哪、記錄多大 | **反組譯** | 只有這份執行檔知道 |
| 這款遊戲**選了**哪一個分頻值 | 反組譯（但先知道分頻基準才算得出 Hz） | 兩者要合起來才有答案 |

⚠ 中間那一欄常常被寫成「未解」，其實只是**問錯了地方**。
「取樣率解不出來」通常不是資料不夠，是把一個查得到的常數當成要解的謎。

### 為什麼反推特別貴

要從執行檔問出取樣率，得**整條寫入路徑都解對**：
哪個變數存分頻值 → 誰把它寫進計時器 → 那個計時器的時基是多少 →
中斷處理常式每次送幾個位元組。中間任何一環讀錯，答案就錯，
而**錯的答案看起來完全合理**（就是一個幾 kHz 的數字）。
查規格是一步，反推是四步而且每一步都能靜默出錯。

---

## 2. 量測值的正確用途：對帳，不是定案

解不出來的時候常會退而求其次去「量」。量測有用，但**它是對帳不是依據**。

DM 的例子：把 DOS 的取樣壓縮 f 倍去對 Atari ST 版的包絡線，
相關係數 ≥ 0.7 的那幾組落在 **f = 2.14–2.51**，中心約 2.28。
ST 是 5485 Hz，所以 DOS 大約 12.5 kHz。

這個區間**寬到不能當答案**（2.14 與 2.51 差了 17%），
但足以驗證「規格說 12.4 kHz」是同一個數量級。

**寫法**：規格是依據，量測是對帳，兩件事分開寫。
把量測區間釘進測試（「兩版的比值要落在 2.14–2.51」），
這樣哪天有人把常數改回錯的算法，測試會紅。

---

## 3. [核心] 移植版的參數不要共用原版的公式

同一份規則、不同機器，**同名的欄位可能不是同一個意思**。

DM 的音效記錄裡都有 `Period` 欄位：

- Atari ST：`取樣率 = 2.4576 MHz / (4 × Period)`，Period 112 → 5485 Hz
- DOS：Period 照抄在資料裡（112／138／145／150），**但不拿它算取樣率**，
  播放固定 12.4 kHz

拿 ST 的公式去算 DOS 的 Period 會得到 5485 Hz 上下。
**症狀是每個音效都變成低沉的慢速版、長度變成兩倍多——而不會有任何一步報錯。**

### 放在哪一層

不要讓呈現層自己拿欄位去算。開一個**入口**，由資料決定走哪條路：

```go
// 有素材包的音效表就是 DOS 那份，回固定值；否則走 ST 的公式。
func (g *Globals562) SampleRateFor(i int) int {
    if len(g.PackSounds) > 0 {
        return DOSSoundSampleRate      // 12400
    }
    return SoundSampleRate(g.Sounds[i].Period)
}
```

判準要是**資料的性質**（這份資料帶不帶那個區段），不是旗標或版本字串——
旗標會忘記設，而忘記設的症狀同樣是安靜的。

⚠ **所有讀取點都要改。** 遊戲本體、匯出工具、除錯用的傾印指令都會各自
拿 `Period` 去算。漏掉一個的話，「玩起來對、匯出的 WAV 不對」這種問題
會被誤讀成匯出器壞了。

### 原始欄位照抄，但不用它

`Period` 仍然抄進素材包——**它是原始資料**，未解的位元組要能原樣 round-trip。
「存下來」與「拿來算」是兩件事。

---

## 4. 中間格式不要內嵌播放參數

取樣資料存**原始位元組**，不要存 WAV。

WAV 的檔頭要填一個取樣率，而取樣率是**播放時**的決定。
存 WAV 就等於在解碼階段先發明一個值，而那個值之後改不掉
（檔案已經散出去了，而且沒人記得它是猜的）。

清單的備註欄寫「播放取樣率 N Hz（見 docs/…）」，把決定留在文件與程式碼裡。

---

## 5. 收尾：把「未解」改寫成現況

規格定案之後，`未解` 那一節要**改寫成答案**，不是在後面補一段「後來查到了」。
散落各處的「取樣率未解」字串（清單備註、規格文件、程式碼註解）要一起改——
留一個在那裡，下一個人就會照著它再研究一次。
