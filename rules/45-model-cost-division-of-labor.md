# 模型成本分工 — 貴的模型留給判斷，粗活交給便宜的

用高階（貴）模型的 session 裡，最容易浪費的方式是拿它做「不吃判斷力的機械工作」：
對碼盤點、逐斷言核實、grep 比對、檔案清單巡查。這些工作便宜模型做得一樣好。

> 來源：用旗艦模型 review 一個多主題原始碼分析知識庫。fan-out 派了多個「專家/學生 review sub-agent」
> 全部繼承旗艦模型，被使用者兩度手動停掉：「太貴」「用貴的 model 分析爛程式價值不高」。
> 事後看，那些 agent 做的事（抽斷言→grep 原始碼→回報不符）確實不需要旗艦判斷力。

## 硬規則

- **不要預設 fan-out review/核實 sub-agent**，尤其在高階模型 session——sub-agent 預設繼承主迴圈模型，
  一次派四個等於燒四倍。要派就先講成本、或明確指定 `model: haiku` / `model: sonnet`。
- **依工作性質切模型**：判斷、取捨、寫作、架構理解 → 高階模型；機械核實、盤點、比對 → 便宜模型
  （主迴圈 `/model` 切換，或 sub-agent 帶 model 參數）。拿不準就先用 inline 的少量 grep 抽驗代替 fan-out。
- **筆記/分析寫到「夠用」就停**：深挖的價值集中在架構、機制、柵欄（Chesterton's Fence）與跨主題連結；
  檔案級長尾投報比低，登進 PLAN/worklist 待辦即可，之後「用到哪、修到哪」被動維護。
- **review 文件時抽「可驗證斷言」回原始碼 grep**，比重讀全文便宜且有效——文件斷言會過期，
  code 才是唯一真相（配 [`63-truth-in-code-not-stale-markers`](63-truth-in-code-not-stale-markers.md)）。

## Why

- token 費用與價值不成正比的工作，換便宜模型後品質不變、成本降一個量級。
- 「全部交給旗艦」和「全部省著用」都是懶惰的預設；成本分工本身就是一個要動腦的架構決策。
- 使用者對成本的敏感度是真實約束——被喊停一次就該把這條寫成規則，不是下次再犯。
## 正面 SOP:旗艦(Fable/Opus)當主模型時的主動派工模式

> 來源:某 retro RE 專案的多輪實踐(使用者指示「簡單工作派便宜模型,分配交給你,≤3 併發」),
> 一輪內 haiku×2 + sonnet×3 + 旗艦架構/驗收,全部交付通過把關。

- **依性質分派**(不是依「重要性」——重要但機械的工作照樣派低階):
  - `haiku`:資料整理/表格萃取(攻略挖表)、機械跑既有工具+驗證(批次匯出資產)、檔案盤點。
  - `sonnet`:有既定方法論的 RE(工具與知識庫齊備、prompt 給足錨點位址)、套件級實作
    (明確規格+單測+「只動哪些檔」邊界)、負面結論查證。
  - **旗艦自己做**:架構級改動(主迴圈/狀態機)、跨模組接線、規格判斷、**每件交付的抽驗把關**。
- **prompt 要素**(便宜模型產出品質取決於此):工作目錄與工具的完整呼叫範例、已知錨點
  (位址/檔案/既有文件「先讀」清單)、明確產出物與格式、**「只動哪些檔」邊界**(避免與主迴圈
  改同檔衝突——main.go 這類熱點只留旗艦動)、「不 commit/push,回報 X」收尾協定。
- **把關不可省**:每件交付先抽驗再 commit(資料→抽樣驗結構/統計;RE→重跑關鍵證據一條;
  code→跑測試+build+截圖)。把關成本遠低於盲信錯誤產出的返工。
- **給 agent 的規格寫「預設值+查證優先」**:好的 agent 會拿文獻推翻你的猜測值(如術語/數值校正案例),
  規格裡明說「查得明確依據就不套預設」。
- 併發上限依使用者指示(該案例 ≤3);互不衝突的檔案邊界是併發的前提。

## [HARD] 旗艦別自己做機械活 —— 主模型的時間=最貴的 token

> 來源：某 retro 專案的宣傳片/打包工作，使用者心疼旗艦模型親自操刀燒額度。教訓：即使旗艦「做得穩」，
> **穩 ≠ 該旗艦做**。旗艦每一步互動（跑指令、抽幀、看圖迭代）都是最貴的 token，機械活自己扛是浪費。

- **這些一律派便宜 agent，不要旗艦逐步手動跑**：
  - **截圖/錄影/影片合成**：x11grab 錄製、逐幀抽圖對照、ffmpeg 合成迭代、montage 拼圖。寫好腳本讓
    agent 一次跑完、只回報關鍵結果幀（而非旗艦錄三次+抽十幀自己看）。
  - **試錯型調參**：一個效果要試好幾組參數（過場加速倍率、截圖 frame、音量正規化值）→ agent 一次跑
    整組 + 回報對照，旗艦只挑定案，不要旗艦一組一組手動試。
  - **批次驗證**：多檔 build/test/截圖、大量對照圖判讀。
- **旗艦只留**：定案判斷（哪個效果對）、關鍵幀的最終確認（1-2 張，不逐幀）、規格與把關。
- **少來回鐵則**：同一件事若旗艦已手動試 ≥2 次（重錄、重截、重調），立刻停手改「寫規格派 agent 跑完整組」。
- **驗收從簡省 vision token**：能用文字/數據（ffprobe/wc/grep/像素 diff 數值）確認的就不抽圖；抽圖是
  vision token，貴——只在「非看不可」（視覺對齊/配色/構圖）時抽，且抽最少張。
- **不主動加碼**：做完使用者要的就停，不自己延伸下一個「順便做」（省的是整段額外互動的 token）。
- **Why**：正面 SOP 講「派工提升產出」；本節講「派工省主模型 token」。同一動作，旗艦自己做
  =最貴時薪掃地；派 agent=旗艦只簽核。使用者額度有限，穩定不是揮霍的藉口。
