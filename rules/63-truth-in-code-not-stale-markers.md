# 唯一真相在 code:別重查已完成的工作、dated 文件會過期、記憶只存教訓

> 情境型紀律(按需)。長專案多輪協作時,**狀態散在 markdown/worklist/記憶裡會彼此衝突**,
> 害你把「早就做完的」當「沒做」又重查一遍(鬼打牆),或拿過期 audit 當現況下錯結論。
> 與 [`62-static-provenance-trace`](62-static-provenance-trace.md)(斷言機制前先靜態驗證)、
> [`60-feedback-loop-priority`](60-feedback-loop-priority.md) 互補:62/60 講「驗 *機制/bug*」,本檔講「驗 *狀態:誰做了沒*」。

## 核心鐵則

- **[HARD] 動手調查任何「剩餘/未完成/未接/待辦」項前,先 `grep` 實際 code 確認它是否已實作。**
  `[ ]` checkbox、「未接」「待 RE」「TODO」這類 marker **不可信**——它們反映寫下當時,不反映現在。
  code(或實際產物)才是唯一真相。漏查就動手 = 把做完的工作重做一遍。
- **[HARD] 驗證完是「已完成」→ 當下立刻在 worklist 標 `[x]` + 收進「已完成」摘要,別留 `[]` 給下一輪重踩。**
  狀態更新是完成工作的一部分,不是「之後再整理」。
- **單一真相來源**:專案狀態(誰做了沒)只放**一處**(worklist / code),其他文件引用它、不複製狀態。
  接到「繼續做 worklist」→ 先把整份對 code 核實一遍,把 stale `[ ]` 清成 `[x]`,再挑真正剩餘的做。

## dated 盤點 / audit / 「剩餘工作」文件會過期

- 這類文件記錄「**當時**狀態」;工作完成卻沒回頭改 → 後來把已完成項當缺口、把已定案的當「未定」。
- **完成一段工作時,順手把對應 audit 文件的該項標 ✅。** 定期(尤其使用者喊「review/清理」時)
  **逐項對 code 核實**:**錯誤斷言(說錯,非只 stale)直接刪除/更正,不只加註**;
  保留作歷史的盤點加「★ 歷史快照,核實以 code 為準」警示。
- **連「教訓檔 / 方法論文件」自己都會過期**:寫 lessons-learned / 設計筆記時,**只寫方法,別釘死會漂的具體數字**
  (測試數、進度%、版本號、檔案大小)——那些一律指向「以實跑/code 為準」。實例:某 lessons 檔釘了
  `game_tester 79/79`,後來變 93/93,反而成了它自己警告的「過時記憶」。耐用的教訓 = 可重複的做法,不是當時的快照值。
- **大規模文件審查用 parallel agent 對 code 核實**:文件多(數十~上百篇 md)時,**fan-out 多個 read-only agent**
  各審一批,任務統一為「抽出可驗證斷言(檔名/函式/旗標/數字/完成狀態)→ grep 實際 code 核實 → 只回報已證實過期者」,
  主執行緒彙整 + 自己改(agent 不改檔)。比逐篇人工掃快且不漏;且常順帶揪出真實回歸(不只文件 stale)。

## 斷言「做了 / 沒做 / 會動」前先驗證

- 宣告完成**只在** `git diff/log/status` + 檔案中介數字(`PASS=N`)驗證後;工具 stdout 回顯最不可靠(會幻覺)。
- 視覺/UI feature:**dump + pixel-diff + 肉眼確認**,不靠「應該會動」。
- 描述一段碼做什麼前,grep 它的呼叫端(真被執行嗎?方向對嗎?)。

## 記憶衛生:存「教訓」不存「狀態」

- 跨 session 記憶放**耐用的方法論 / 流程教訓 / 已驗證事實**(這些不會過期)。
- **專案狀態(進度、誰做了沒)放 worklist/code,不放記憶。** 如此記憶永遠正確、狀態永遠在一處。
- 接到「review 記憶是否同步」→ 記憶若是教訓/事實=保留;若混進了會變動的狀態快照=那本來就不該放記憶。

## 改「已測試系統」:用「可選參數 + 預設=現行」做零回歸

- 要改一個有單測護著的系統時,**新增 `_variant`(帶新參數),舊函式 = 呼叫 `_variant(…, 預設值)`**;
  設計成 **預設值完全重現現行行為** → 既有測試零修改全綠,呼叫端傳新值才得新行為。新行為另加單測。
- 例:把確定性算法改成可選 rng —— `rng==NULL` 等同現行確定性,既有測試不動。

## Why

- 多輪協作最大的隱形成本不是「不會做」,是「**把做過的當沒做又做一遍**」+「**信了過期文件下錯結論**」。
- 根因都一樣:**狀態的真相分散且未同步**。對策一致:**code 是唯一真相,marker 一律回 code 核實,
  完成即更新狀態,記憶只存教訓。**
