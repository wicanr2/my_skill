# 復古遊戲 remake／中文化 README 鐵則

README 是專案穩定首頁：讓第一次到訪的人理解「這是什麼、為何保存、現在能做什麼、
如何合法執行、哪些聲明有證據」。它不是逐輪工作日誌、完整研究資料庫或宣傳文案堆疊。

本規則以近期 `mm2`、`dragon`、`fd2` README 的有效結構為參考。作品可以採歷史敘事、
技術紀錄、遊戲介紹或適度懷舊語氣，但不得強迫每個專案都寫成第一人稱書信或 1990s
雜誌體；語氣永遠不能蓋過版本、授權、現況與證據的精確性。

## 穩定骨架

依專案需要採用以下順序；沒有真實內容的章節可以省略：

1. 標題與一句定位：原版版本、重製技術、保存目的。
2. 法律與原版資產邊界：玩家自備合法原版；不進 Git／發行包的內容。
3. 遊戲與保存價值：核心玩家循環，以及為何不能只做單一畫面或子系統。
4. 現況摘要：正常玩家路徑已接通什麼、尚缺什麼、唯一現況入口在哪裡。
5. 重要發現與可驗證成果：代表性格式、規則、中文化、音訊或跨平台成果；每項連證據。
6. 執行期或同狀態比較圖：caption 說清楚來源、狀態、模式與證明邊界。
7. 最短安全執行／匯入方法：必要依賴、Docker、原版資料位置與失敗即關閉條件。
8. 文件導航：`CONTEXT.md`、狀態頁、spec 索引、RE 索引、驗證矩陣、發行說明。
9. 授權、致謝及與原權利人無隸屬關係聲明。

## 證據與現況契約

- README 可以保存一個目前 milestone／release 的摘要，但逐輪日期、命令、失敗、commit、
  checkpoint 與研究流水帳一律寫入 `WORKLOG.md`／`RESEARCH-LOG.md`。
- 完成百分比必須交代分母、量法、未知與外部驗收；函式覆蓋率、綠色單元測試、資料表
  數量或 debug-assisted path 不等於可玩完成度。
- 「完整可玩」「逐像素相同」「已通關」必須限定版本、狀態、樣本與正常玩家路徑，
  並連到 verification matrix 或同狀態證據。
- research dump、原版畫面、remake runtime、prototype 與宣傳片素材要明確標示，不能互相冒充。
- 即時數字只維護一份詳細真相來源；README 摘要連過去，不複製多份會漂移的矩陣。

## 寫作方式

- 橫向比較用表格；操作順序用編號；警告用條列；保存意義與技術發現用短段落敘述。
- 每個長表格前先說它回答什麼，表格後說明數字的限制；不要讓表格自行暗示完成度。
- 技術名詞、位址與檔名保留原文，但使用完整中文句型包覆。
- 故事、開發史、時代評論與譯名考古只有在有來源且有助理解時加入；引用第三方內容
  採短引、摘要與出處，不收錄整篇受保護文章。
- README 超過一般讀者可導航的長度時，把深層工程內容移到 docs，首頁保留結論與連結。

## 禁止事項

- 不把 README 寫成日期倒序工作日誌、過期 worklist、完整函式 census 或未分級假說清單。
- 不內嵌或提交未授權的原版程式、ROM、資料、美術、音樂、字型或完整媒體。
- 不把 direct-entry、座標注入、forced-win、單張截圖或測試 fixture 冒充自然玩家路徑。
- 不用「幾乎完成」「100%」等宣傳詞取代可回查的分母與剩餘門檻。
- 不為了懷舊氣氛發明個人回憶、雜誌引文、譯名故事或原開發史。

## 校對門檻

重大 README 編輯後必須檢查：標題層級、相對連結、圖片與 caption、命令、平台版本、
現況數字、資產／授權邊界、README／WORKLOG 分工，以及所有完成／parity 聲明是否能回到
目前程式、READY／CONFORMED spec 或正常玩家驗證證據。
