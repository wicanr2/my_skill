# 去 AI 味 (De-slop) 檢查表

刪掉「一看就是 AI 生成」的中文寫作痕跡。與 `90-plain-language` 互補:90 規定白話正面怎麼寫,本檔規定 AI slop 反面怎麼刪。來源:Wikipedia「Signs of AI writing」(WikiProject AI Cleanup)/ humanizer skill,取其跨語言有效的部分並做中文適配。

已被 核心文風規則(meta 標籤禁令、浮誇/絕對化禁令、中性客觀)與 `90-plain-language`(結論先行、具體勝抽象、空泛結尾)涵蓋的條目不在此重列。本檔只放增量項。

## 詞與句法

- **AI 詞黑名單**:第一次看到就換成具體說法,別放進交付稿。常見:賦能、重塑、打造、絲滑、無縫、格局、生態、深度(賦能)、強大、靈活、可擴展、極致、顛覆、革命性、閉環、抓手、對齊顆粒度。
  - 壞:這套架構徹底重塑了調度的格局。 好:這套架構把派工與避塞車拆成兩個獨立模組。
- **copula 迴避**:把「作為…的存在 / 扮演著…的角色 / 堪稱…的里程碑」改回「是 / 負責」,或直接刪。
  - 壞:reference_coordinates 扮演著座標對齊的關鍵角色。 好:reference_coordinates 負責把車本地座標對齊到世界座標。
- **負面對立濫用**:「不僅…更是…」「與其說…不如說…」當開場套式時拆成正常句。
  - 壞:這不只是工程問題,更是一面映照架構的鏡子。 好:這是工程問題,根因在責任分層放錯地方。
- **強湊三段式**:硬湊三個並列詞(更快、更穩、更強)改成講清楚實際改了幾項、各是什麼,有數字配數字。
  - 壞:讓系統更高效、更智慧、更可靠。 好:接駁段改用倒車後,單次取貨少繞約 4 公尺。

## 修辭膨脹

- **權威揭示腔**:「真正的問題在於 / 歸根結底 / 本質上 / 說到底」後面常只是普通結論,刪掉框架直接講那句結論。
- **格言公式**:「X 是 Y 的鏡子 / 縮影 / 語言 / 縮寫」這種偽金句,換成它想講的具體主張。
  - 壞:對稱是信任的語言。 好:對稱的版面通常讓使用者覺得比較好預期。
- **金句化堆疊**:不要每句都像名言收尾、短句連打製造戲劇感。單一短句強調可以,連續一串就成了人工感。改平鋪直敘。
- **假範圍**:「從 X 到 Y」但 X、Y 不在同一尺度時,直接列舉實際涵蓋什麼。
  - 壞:從建圖到調度、從感測到決策,無所不包。 好:涵蓋建圖、定位、路徑規劃、多機調度四塊。

## 結構與冗詞

- **-ing 尾巴(中文版)**:句尾掛「凸顯了 / 體現了 / 反映出…的重要性」「為…奠定基礎」「為…提供寶貴啟示」充深度,刪掉。
- **filler / hedging**:「進行…的動作」→ 動詞本身;「具備…的能力」→「能…」;「在…的情況下」→「…時」;「可能、或許、大致、也許」疊用時只留一個。
- **粗體列表症**:`- **效率:** 大幅提升` 這種 inline-header 列表、每行粗體開頭的機械式排版,改成散文或精簡條列,粗體只留真正要強調的。

## 去 slop 審查 loop

寫完一版後,跑一次三步:

1. **draft** — 先把意思寫完整。
2. **audit** — 自問一句「這段哪裡還像 AI?」,把剩餘 tell 列出來(節奏太均勻、還有黑名單詞、結論空泛…)。
3. **final** — 針對那些 tell 再改一版。

對外 / 客戶 / 管理層 / 正式技術文件必跑;內部草稿可略。

## false-positive 清單(防改過頭)

下列**單獨出現時不是** AI tell,別為了「去 AI 味」把人話也鏟掉。看**成串**的 tell 才動手,不是單一:

- 工整文法、被編輯過的乾淨文筆。
- 夾雜正式與口語(常是技術人或年輕寫作者的習慣)。
- 平實、乾燥但沒有具體 tell 的散文 —— 那只是樸素,不是 AI。
- 專業 / 學術術語本身(AI 是濫用**特定**花俏詞,不是所有正式詞)。
- 缺引用、單一轉折詞、長短句交錯 —— 這些本來就常見。

保留這些「人味」訊號,不要改掉:具體到難以捏造的細節、混合情緒或未決張力、寫作者說得出理由的編輯選擇、自我插話與括號補充。

## 其他

- **diff-anchored writing**:文件描述「東西現在是什麼」,不是「相對上一版改了什麼」(changelog / release note / 遷移指南除外)。

## 何時套用

- 寫完對外 / 客戶 / 管理層交付、README、計畫書、簡報文字、技術文件後,過一遍。
- 與 `90-plain-language` 七準則一起用:90 先把白話寫對,91 再把 slop 刪掉。
- 衝突時依 核心文風規則 最高優先原則,正確性 / 領域用詞優先,不為了「去 AI 味」改動數字、結論或專案術語。
