# 字模索引文本還原（老遊戲中文不是 Big5 時）

有一類 1990s 中文 DOS 遊戲，**畫面上滿滿中文，但整個遊戲目錄 grep 不到一個 Big5 碼點**。
不是加密，是它根本不存文字：它存的是「畫第幾個字模」。原文散在字模與索引之間，
要還原成可讀可改的文字，得把兩邊接起來。

## 1. 辨識訊號（三個同時成立就幾乎確定）

| 訊號 | 怎麼驗 |
|---|---|
| 執行檔與資料檔的 Big5 命中數是 **零** | `iconv -f BIG5 -t UTF-8 -c FILE \| grep -oP '[\x{4e00}-\x{9fff}]{2,}'` 逐檔跑 |
| 有一批小字型檔，大小**整除字模 stride** | 16×15→30、16×16→32、24×24→72、16×24→48。整除率 100% 才算 |
| 字型檔**數量多、每個都小**，且命名帶場景編號 | `TN15.1`–`TN15.39` 這種。單檔字數 30–800，遠小於 Big5 全字庫 13,094 |

驗第二項時**直接渲染前兩個字**（每列 `(W+7)/8` bytes、MSB-first、由上而下）。
畫出來是可辨識的漢字就結案，不要只看整除性——整除是必要不是充分條件。

## 2. 為什麼會這樣設計（第一性原理）

DOS 沒有內建中文。遊戲若不要求玩家先掛倚天／零壹中文系統，就得自帶字型。
而倚天 16×15 全字庫是 13,094 字 × 30 B ≈ **393 KB** —— 1992 年一張 1.44 MB 磁片放不下
全字庫加遊戲。於是：

> 只帶這個場景用得到的字，文字改存「第 N 個字模」。

副作用有三個，做逆向時都會遇到：

1. **省空間**：全字庫 393 KB → 每場景幾 KB。
2. **反修改**：改文字要同時改字模與索引，當年的修改器動不了。
3. **文字與呈現綁死**：同一句話在不同場景的索引不同，因為字表不同。

理解這一層之後，後面每個陷阱都是這個設計的必然結果，不是隨機的坑。

## 3. 還原鏈（四步，缺一不可）

```
場景字模檔 ── 逐 byte 比對 ──▶ 倚天全字庫 ──▶ Big5 碼點
                                                 │
索引序列（從繪字呼叫端反追出來） ─────────────────┘
                          ▼
                    可讀可改的原文
                          ▼
              重新編碼 → 逐像素比對原版截圖
```

### 3.1 字模反查 Big5

拿倚天 `STDFONT.15`／`SPCFONT.15` 建反向表（見 kb `eten-bitmap-font`，
Big5 分區索引公式在那裡，不要重推）：

```python
# 30 B 的字模 bytes 直接當 key，O(1) 反查
rev = {}
for idx in range(13094):
    rev[std[idx*30:(idx+1)*30]] = big5_of_index(idx)   # 分區公式見 eten-bitmap-font
```

**先驗 oracle 再跑全量**：`idx=0` 必須是「一」，「中」(A4A4)、「猴」(B555) 渲染出來
必須可辨識。這關沒過就整批偏移，症狀是「有字但都不對」。

### 3.2 索引來源

字模找到了，還要知道「哪一串數字代表哪一句話」。**從繪字函式的呼叫端往回追**——
先在反組譯裡定位「載入字模檔 → 依索引取 30 B → 畫到螢幕」那條路徑，
再看索引是從哪個緩衝區來的。這是 `rulebook/62`（靜態反追溯源）的標準應用。

**不要猜索引格式。** 猜三次沒中就停手去讀反組譯（`rulebook/62`、`64`）。

#### [特例] 先確認「真的有索引層」再去追它

動手追索引之前，先花五分鐘做一件更便宜的事：**把字模檔整份反查成字，直接讀讀看**。

有一種變體**根本沒有索引層**——字模序列本身就是文本，每 `w` 個字模一個詞條，
不足的格子填全零字模，程式從 `k × w × 30` 直接取 bytes 送繪圖 API。
這種情況下 Big5 零命中的原因不是「存了索引」，而是**原始碼裡本來就沒有碼點**，
去反組譯裡找索引緩衝區會一無所獲。

辨識訊號（反查完立刻看得出來）：

| 訊號 | 意義 |
|---|---|
| 反查出的字**直接連讀就是通順詞條**（`蔣中正何應欽馮玉祥`）| 沒有索引層，字模序列即文本 |
| 空白字模佔比高（20%+）且**位置有規律** | 定長槽位的排版填充，不是缺字 |
| 檔案字模數整除某個小數字 `w`，且每個 `w` 段落語意完整 | 槽寬 = `w` |

判 `w` 不要靠肉眼。對每個候選 `w`（字模數的因數）檢查各槽位的非空分布是否符合
**全滿／靠左／靠右／置中／分散對齊**之一，取符合率最高者；平手時**取排版種類最少的**
——小的 `w` 常是真值的因數，會把詞條攔腰切開，碎片剛好散落成各種對齊，符合率一樣 100%
但模式雜亂。真正的槽寬對齊方式是一致的。

三個會讓這套判準失效的情況，遇到就改用內容語意判定並**標記證據較弱**：

1. **零空白的檔案**（詞條剛好填滿）——沒有空白可資判別，任何 `w` 都是「全滿」。
2. **空白在詞條中間**——那是執行期填數字的佔位（`第␣集團軍`→`第三集團軍`），
   不屬於任何一種對齊。這種檔通常還是有索引式取字：數字字模從另一個單字表取。
3. **字模數是質數**——多半根本不是定長詞條，而是單字表。

**通則仍是索引式**（省空間的動機一樣成立）。無索引的變體出現在
**詞表類檔案**（地名、人名、番號、選單詞彙）——這些本來就是定長的短詞，
排版填充的浪費小於索引表的成本。同一款遊戲的**敘事文本**（事件、對話、劇情）
仍可能是索引流，兩者並存不矛盾。**別因為詞表沒有索引就下結論說整款遊戲都沒有。**

### 3.3 逐像素 round-trip

還原出來的原文，重新編成索引 + 字模，畫出來要與原版截圖**逐像素相同**。
肉眼看起來對不算數——字模順序差一格、全形空白判錯，肉眼都看不出來。
這是唯一可信的驗收標準（同 `rulebook/65`：對 reference 驗，不是對自己的測試驗）。

### 3.4 例外記帳

反查不到的字模、字數與索引範圍對不上的場景，全部列進格式文件。
那些通常就是**遊戲自製字**（商標、特殊符號、當年缺字自己畫的）。
`rulebook/83`：完整性 > 投報，不准以「只有幾個字」為由跳過。

## 4. 五個陷阱

1. **索引是檔內序號，不是全域編號。** 同一個索引在別的場景是別的字。
   還原出來的文字必須連「哪個字表」一起記，否則回填時整段變亂碼。
2. **字模順序通常是「首次出現順序」，不是 Big5 順序。** 別假設可以用排序反推。
3. **自製字反查會落空。** 雜湊比對落空的字模，改用相似度（逐 bit hamming distance）
   對全字庫排序，取前 10 名人工判讀。多半是改過筆劃的近似字。
4. **字模檔裡可能混放圖像。** 大小整除但渲染出來不是字的那幾筆，先當圖處理，別硬解。
5. **索引可能不連續。** 控制碼（換行、換頁、顏色、等待按鍵）會混在索引流裡。
   先把控制碼的語意解乾淨，再談抽字——這層沒解，多語系的排版一定會爆。

## 5. remake 該怎麼處理

- **原版機制要完整記錄**進格式文件，那是保存的一部分。
- **但重寫版不沿用**。字模子集是 1990 年代磁片容量的產物，不是設計意圖。
  remake 用真正的字串表 + 完整字型，索引機制到此為止，不進執行路徑。
- 多語系（英／日）本來就無法沿用中文字模索引，這條界線要在架構初期就畫好。

## 6. 案例

**《大時代的故事》**（漢堂國際資訊，1992，DOS，`~/cht/大時代的故事/`，
repo [`great-era-remake`](https://github.com/wicanr2/great-era-remake)）
—— **這是 §3.2「沒有索引層」那個特例的實證案例，不是通則的代表**。

辨識訊號全部命中：51 個 `.15` 族檔案大小整除 30、渲染出可辨識字形、
五個執行檔與 `GRT.GLB`／所有 `.DAT` 的 Big5 命中數為零。

但照通則去反組譯追索引會白做工。實際做法是先把 51 檔整份反查
（6,174 字模：倚天命中 4,799、空白 1,374、例外 1），反查完直接連讀就是通順詞條
（`蔣中正何應欽馮玉祥`、`調動軍事運補徵稅`），**索引層根本不存在**。
槽寬 `w` 由空白排版模式判定：`TN15.N` 地名 `w=5` 靠左、`MAN*` 人名 `w=3` 分散對齊、
`JAPAN*` 日將名 `w=5` 靠右。46 檔判得出來，5 檔（零空白或空白在中間）只能靠語意。

兩個延伸教訓：

- **例外要追到底**：唯一反查不到的字模，用二維位移窮舉確認是倚天「，」
  左移 3 px、下移 2 列。追完才敢說「字形 100% 出自倚天」（`rulebook/83`）。
- **詞表沒有索引 ≠ 全遊戲沒有索引**：DOSBox 實測發現畫面上的長句
  （`北伐時期 — 國民革命軍崛起`）不在任何字模檔裡，敘事文本另有來源，仍可能是索引流。
