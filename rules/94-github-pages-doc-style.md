# 技術文件網站版面規範（GitHub Pages / 單頁工具）

做給人**閱讀**的技術文件站、筆記站、單頁工具的版面規則。核心主張只有一句：

> **層級用線條、留白、字級對比建立，不用卡片與色塊。**

適用於 GitHub Pages、Jekyll 主題覆寫、單檔 HTML 工具頁、以及任何「內容是重點、裝飾不是」的網頁。
配合 `90-plain-language`（怎麼寫）與 `91-deslop-ai-writing`（刪 AI 味）使用——那兩份管文字，本檔管版面。

---

## 一、硬禁令

違反這幾條，成品會立刻被認出是「AI 隨手生的網頁」。**除非使用者明確要求，一律不做：**

- **不用卡片建立層級或對齊。** 圓角矩形、方形卡、帶色邊條的卡片一律不用。
  分組要靠：一條細分隔線、一段留白、或字級與字重的落差。
- **不用藍白配色與藍紫漸層。** 也不用青紫霓虹、彩虹光暈、毛玻璃（glassmorphism）、發光邊框。
  這幾樣是目前最強的「AI 生成」訊號。
- **不用紅紫黃綠同時出現在一頁的配色。**
- **不用等分版面當預設。** 三等分、四等分、2×2 矩陣、「標題 + 三個並排區塊 + 結論」都是公式化的偷懶解。
  資訊有三四項不代表就要三四個格子。
- **不用通用陰影、雜訊、粒子、無意義漸層。**
- **技術內容偏好直角。** 圓角最多 2px；圓形與曲線只在語意需要時出現。
- **圖示要來自同一套筆畫系統。** 不要混用 emoji、3D 圖示、擬真圖示與系統預設圖示。

## 二、層級怎麼建立

| 手段 | 用法 |
|---|---|
| **細線** | `h2` 上方一條 1px 線就足以分節；`h1` 下方用 2px 深色線收住 |
| **留白** | 區塊間距的落差比任何邊框都清楚。`h2` 上方留白要明顯大於下方 |
| **字級** | 相鄰層級差 20–30% 即可辨識，不需要差一倍 |
| **字重** | 正文 400、強調 600–660。不要用 700 以上的粗體當常態 |
| **顏色深淺** | 正文最深、次要說明淺一階、輔助資訊再淺一階。同一個色相，只變明度 |

容器（panel）只在**內容真的需要邊界**時使用：程式碼、設定檔、系統範圍框、關鍵結論。
用直角或極小圓角、細框線、淡填色，不加陰影。

## 三、色彩系統的組織方式

不要挑「好看的顏色」，要先定**每個顏色的語意**，全站固定不變：

```
背景色    紙面，長文閱讀用淺色
結構色    分隔線、表格線、邊界（中性灰，兩階：細線 / 較明顯的線）
關鍵路徑色  連結、當前位置、需要被讀到的那一項（全站只有一個）
狀態色    ok / warn / bad，只用在狀態
中性色    正文、次要文字、輔助文字（同色相變明度）
```

一個顏色一個意思，出現在哪裡都代表同一件事。**關鍵路徑色只有一個**——多一個就開始互相搶。

避開藍色是繞開「藍白 AI 配色」最省事的做法：暖色（鏽橙、赭紅）、墨綠、深靛都可以，選一個就固定。

深色模式用同一組語意變數換值，不要另外設計一套。

## 四、字體

- 正文與標題用**高易讀性的無襯線**；需要文件感時標題可用克制的襯線。
- 程式碼、路徑、欄位名、數字用**等寬**。
- **一個站最多兩個字族。** 層級靠字級與字重，不靠換字體。
- 中文要在字族堆疊裡明確指定（`Noto Sans TC`、`PingFang TC`、`Microsoft JhengHei`），
  不要只寫 `sans-serif` 就當作有處理。
- 內容變多時，**先精簡文字、拆頁、調整圖文比例**，最後才微調字級。

## 五、表格、程式碼、圖表

**表格**
- 只用細分隔線。**不要粗外框、不要彩色表頭、不要斑馬紋。**
- 表頭用小字級 + 中性色 + 字距，不用填色。
- 數字欄右對齊、等寬字、`font-variant-numeric: tabular-nums`，按小數點或單位對齊。
- 缺漏與不可比的項目要明確標記，不要留空白讓人猜。
- 寬表要有水平捲動容器，不能撐破版面。

**程式碼**
- 只留支撐論點的最小片段，並先告訴讀者要看哪裡。
- 直角或 2px 圓角、細框、淡填色、無陰影。
- 語法高亮只用來凸顯關鍵行或差異，不要整段花花綠綠。

**圖表**
- 移除預設外框、3D 效果、漸層、粗格線、無意義圖例。
- 主序列用關鍵路徑色，基準線與次要序列退成灰階。
- 關鍵值、轉折點、異常值直接標在圖上，並寫出「這代表什麼」。
- 量測條件（環境、版本、負載、樣本、單位、基準）貼著圖放。

**架構圖與流程圖**
- 箭頭要有方向與意義；必要時標協定、資料、頻率、容量、觸發條件。
- 區分資料流、控制流、例外路徑。
- 連接線終止於節點邊緣，不穿過文字；交叉太多就重排或拆頁。
- 關鍵路徑加粗或用關鍵色，其餘退為中性；不加光暈、不用 3D 箭頭。

## 六、來源標註

涉及外部事實與數據的段落，**必須寫出來源、日期或時間區間、量測基準**，
並用超連結指向原始報告或資料頁。這不只是誠信問題，也是專業感的來源。

價格、benchmark 這類會過期的數字，要標**基準日**，並讓讀者能一鍵核對。

## 七、中文排版的垂直節奏

中文字身比拉丁字母大、字間沒有空格，同一組數值在英文版讀起來剛好，中文版就是「擠在一起」。

| 項目 | 數值 | 理由 |
|---|---|---|
| 內文行高 | 1.9–2.0 | 英文常用的 1.5–1.6 套到中文會糊成一塊 |
| 字距 | `.01em` | 微量字距對中文的疏密感影響大於對英文 |
| 段落間距 | **必須大於一個行高** | 小於行距時，段落分界在視覺上不存在 |
| 清單項間距 | ≥ .5rem | 與段距同理 |
| 表格列 padding | ≥ .7rem | 表格是最容易被壓密的地方 |
| 行內 `code` | 左右各 `.12em` 外距 | 沒有外距會直接黏住前後的中文字 |

**字級基準只能有一個。** 內文寫 `px`、標題寫 `rem`，兩者基準不同，
放大內文時標題不會跟著動——`h3` 會變得比內文還小，層級整個反過來。
基準統一放在 `html`，其他一律用 `rem`。

## 八、四個「不實際渲染就看不到」的缺陷

版面規則能靠讀 CSS 檢查，這四個不行——它們只在真實 HTML 結構下出現。
**改完版面必須實際渲染出來看**（`google-chrome --headless --screenshot`，
再把 PNG 讀進來檢視；也可以直接 `curl` 線上頁面套本機 CSS，那是最貼近實際的測法）。

1. **Rouge 的包裝層。** Jekyll 把程式碼渲染成
   `div.language-* > div.highlight > pre`，寫 `main > pre` 的規則
   **一條都不會命中**。要對 `.highlighter-rouge` 下手。
2. **kramdown 的鬆緊混雜清單。** 同一份清單裡，項目之間有空行的會變成
   `<li><p><a>`，沒空行的是 `<li><a>`。只寫其中一種選擇器，畫面上會有幾筆沒套到樣式。
3. **相鄰右對齊欄相黏。** 數字欄設 `padding-right:0` 貼齊右緣，
   兩個右對齊欄相鄰時數字會連在一起（`16` 和 `2:1` 讀成 `162:1`）。
   只有**最後一欄**能貼齊。
4. **破格寬度被自己的 padding 抵消。** `width:calc(100% + 6rem)` 配
   `padding:0 3rem` 在 `border-box` 下內容寬度完全沒變，看起來像沒生效。

**破格要內容驅動。** 寬表往兩側撐開是為了少斷行，但四欄的表撐到同樣寬度只會讓欄距散開。
判斷條件（欄數 ≥5 或實際溢出）交給 JS 掛 class，不要一律套用。

## 九、交付前自檢

- 把文字遮起來看，還認得出這是哪一類文件嗎？還是像任何一個 AI 產生的網頁？
- 有沒有為了排版整齊而出現的卡片牆、等分格子？
- 每個顏色在全站的意思一致嗎？關鍵路徑色是不是只有一個？
- 表格有沒有粗外框或彩色表頭？數字有沒有對齊？
- 外部數據有沒有來源、日期與量測基準？
- 視覺重量有沒有落在證據上，而不是落在標題與裝飾上？
- **有沒有實際把頁面渲染出來看過？**（只驗 HTTP 200 與建置成功不算）
- 段落間距是不是大於一個行高？`h3` 是不是比內文大？
