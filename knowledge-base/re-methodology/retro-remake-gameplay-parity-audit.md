# 復古遊戲 remake 的原版玩法忠實度稽核

> 適用：專案已可玩、功能看似很多，但懷疑規則由 remake／LLM 自行補出；或準備宣稱
> 「忠實重製」「完整 remake」「原版一致性（parity）」之前。
>
> 目標：量測玩家機制的原版證據覆蓋，不以函式數、具名符號數、畫面數、單元測試數或
> remake 消費端數量代替。

## 先下正確結論

把每個系統拆成兩個互不推導的狀態：

1. **remake 工程狀態**：未實作、部分接線、可玩、可存檔、可跨平台。
2. **原版對齊狀態**：已證實、強推論、假說、未知、已證實不一致。

「可玩」不會自動提高原版對齊等級；「已證實不一致」即使遊戲體感合理，也必須回到核心
工作表。現代多人連線、文字安全框、TLS、跨平台打包等可獨立完成，但不增加玩法忠實度。

## 何時必須啟動重新稽核

符合任一項就啟動，不沿用舊完成方框：

- 使用者或測試者從原版影片／實機發現節奏、數值、人工智慧（AI）或結果明顯不同。
- 文件出現「近似」「代理值」「設計性重建」「remake 模型」「手冊沒有寫所以自訂」。
- 原版已有具名函式，實作卻只引用手冊、第三方重製或平衡直覺。
- 測試只呼叫 remake 輔助函式（helper），預期值也是由同一份 remake 公式產生。
- 以「零消費常數」「零覆蓋函式」「探針見底」宣稱逆向接近完成。
- README、Release 或推廣片準備使用「完整」「忠實」「原汁原味」等字樣。

## 稽核前的唯一現況表

先建立當日活表，資料來源優先序為：目前程式與呼叫端、最近可重現測試、原始證據、Git
紀錄、歷史文件。舊 worklist 與舊對話不能單獨重新開啟或關閉工作。

至少記錄：

- 原版輸入檔名、SHA-256、版本與修補版本（patch）。
- IDA 版本、映像修訂版（image revision）、位址空間與資料庫來源。
- 目前 HEAD、工作樹狀態與既有產物日期。
- 哪些是 remake 已完成、哪些是原版未知、哪些是可選現代化。

## 具名符號不是逆向完成度

符號表、除錯符號（debug symbols）、函式索引與漂亮名稱只提供導航。它們不能證明：

- 呼叫端（caller）與實際玩家入口已找到；
- 呼叫慣例（calling convention）與執行期（runtime）參數已解；
- 結構欄位、資料表與單位尺度已對回；
- 亂數產生器（RNG）、分支、版本差異與副作用已理解；
- 回寫、存檔與下一回合消費端（consumer）已接到 remake。

函式數量只能描述分析表面，不可換算成完成百分比。外部符號若曾有 parser 位移、相鄰名稱
衝突或版本差異，須用函式內容錨點與 caller 驗證；名稱本身不得當作證據。

## 玩家機制—原版—remake 證據矩陣

每個玩家可感知機制至少一列，固定欄位如下：

| 欄位 | 必填內容 |
|---|---|
| 系統／玩家路徑 | 玩家如何正常觸發，不用 debug 入口代替 |
| 原版入口 | 原始名稱與線性位址；無名稱仍保留 raw 位址 |
| 呼叫端 | 直接 caller、間接取址端與上游狀態建立者 |
| 原版輸入 | 記錄偏移（record offsets）、資料表、旗標、RNG、版本條件與單位 |
| 原版輸出 | 回傳值、全域／記錄回寫、事件、存檔與下游消費端 |
| Go 消費端 | 型別化資料、規則、UI、存檔及所有平行玩法路徑 |
| remake 狀態 | 未實作／部分／可玩／可存檔／可打包 |
| 原版對齊 | 已證實／強推論／假說／未知／已證實不一致 |
| 驗證 | 同輸入、同 RNG、邊界值、原版實驗或視覺同狀態 |
| 下一閘門 | 下一個最小、可重現且能提高證據等級的行動 |

矩陣先按玩家風險排序：回合與經濟、AI／外交、戰鬥與傷亡、勝利條件、存讀檔，再處理
純視覺 polish。大型 4X／策略遊戲還要為玩家與 AI、快速與戰術、自動與手動等平行路徑分列，
避免只對上一個 helper。

## IDA 深抽樣程序

先用 5–15 個高影響機制作「誠實度探針」，不是先反編完整 executable：

1. 從正常玩家動作找到原版入口，不從 remake 函式名稱反推原版應該存在什麼。
2. 在 `.i64` 查函式邊界、所有直接呼叫端、被呼叫函式與資料交叉參照（data xref）。
3. 查取址端及其後的間接讀寫；直接 xref 少不等於沒有寫入。
4. 記錄原始指令、位址與運算元，再附語意及證據等級，不用推測性改名覆蓋。
5. Hex-Rays 只作輔助。出現 `JUMPOUT`、未定義變數、異常控制流或參數時，退回原始指令、
   堆疊（stack）／暫存器（register）與原始跳躍表（raw jump table）。
6. 追到玩家可見結果及下一個消費端；只解出中間公式不能關閉整個系統。
7. 對回 Go 的實際呼叫端，不只搜尋同名常數或孤立輔助函式。

若抽樣找到一個「已證實不一致」，就推翻「核心玩法已完成」的總體斷言；不必等全部矩陣完成
才修正 README 與活表。

## 防止 remake 自己證明自己

測試來源必須標示：

- **remake 自洽測試**：只證明內部不崩潰、不越界、可重播或公式一致。
- **靜態原版證據測試**：預期值來自可回查的指令、資料表或 bytes。
- **動態原版 oracle**：相同狀態、輸入、seed／RNG 與版本的原版結果。
- **正常玩家路徑**：確認 UI、規則、回寫與存檔整條鏈可達。

禁止讓測試與實作共用同一個自編常數產生預期值（expected value）。固定 RNG 測試必須記原版 RNG 輔助函式、
呼叫次數與狀態更新順序；只使用相同 LCG 不代表結果一致。

## 完成優先後的分層抽樣契約

當使用者明確選擇「先完成 remake、再抽樣驗證」時，仍先定義玩家可見行為母體與風險分層，
不能把方便取得的固定 smoke 當成隨機樣本。至少分開主線探索／事件、戰鬥與傷亡、施法／狀態、
物品／經濟、存讀檔／跨層、繁中 UI，以及替代玩法路徑；各層保存抽樣框、抽樣方法、seed／存檔、
原版與 remake 結果、成功判準及失敗分類。

若驗收目標是玩家可見行為 **99% 近似原作、95% 信心度**：

1. 使用單側 95% Clopper–Pearson 精確二項信賴下限，只有下限 `>= 0.99` 才通過；不得只報點估計。
2. 零失敗時，下限為 `0.05^(1/n)`；因此至少需要 299 個具代表性且可視為獨立的觀察。
3. 有失敗時擴大樣本並重算精確下限；不可刪除不利樣本、事後改成功定義或把同一狀態的逐幀畫面
   虛增成多個獨立觀察。
4. 固定通關腳本、人工挑選、高風險邊界與單元測試仍是必要工程 gate，但若不具隨機代表性，
   不計入 95% 信心度宣稱。
5. 統計結論只涵蓋已定義母體；未抽到的遊戲版本、平台、語言、替代分支或 late-game 狀態必須另列。

### 隊伍全滅的終止規則

- 原版或 remake 中隊伍全滅皆可由正常玩法產生；偵測到全滅後，立即終止該條測試路徑，不在死亡
  狀態後繼續送移動、戰鬥、存檔或劇情輸入，也不把「後續步驟未執行」記成額外失敗。
- 全滅樣本仍必須保留並分類：若原版與 remake 在同一抽樣狀態都全滅，且死亡結果／終止 UI 符合
  成功定義，可算近似成功；若只有一方全滅、全滅時機／原因／結果明顯不同，則算近似失敗。
- 不可因全滅是合法結果就從分母刪除。若測試目標本來就是通關可達性，remake 全滅仍代表該次
  通關路徑未完成；可用新 seed／新樣本另跑，但不得覆蓋原紀錄。
- 測試器應輸出結構化終止原因，例如 `party_wiped`、最後有效步驟、seed、存檔雜湊、原版／remake
  結果與是否計入統計，讓後續彙總不依賴人工記憶。

## 原版資料不足時的行為

依序使用：IDA `.i64` 的呼叫端／交叉參照／資料流、原始位元組、官方手冊與 patch、可授權的外部
資料、原版動態實驗。手冊沒有數字時，不得直接推論 executable 也沒有公式。

若仍不足：

- 玩家功能可以先用近似維持可玩，但命名、文件、測試與發行聲明都必須標 `remake 近似`。
- 不可把近似值包裝成「合理原版值」；保留未知與下一個證據閘門。
- 與玩法無關的 Win95／檔案服務／初始化 helper 可以停止深挖，但不能用這個停止規則豁免核心
  經濟、AI、戰鬥、外交、勝利或存檔語意。

## 關閉與發行閘門

一個系統只有在「原版輸入 → 規則／分支／RNG → 回寫 → Go typed data → 所有主要路徑 → UI／
存檔 → 獨立測試」閉合後，才可標原版已證實。函式名稱、單一公式、綠色 Go 測試或一張相似
截圖都不夠。

核心矩陣未閉合前：

- 發行包稱「可玩 remake 預覽」；不稱完整原版重製。
- README 分開列已完成工程能力與原版對齊工作。
- 每次推翻舊結論時，活表刪除錯誤現況；研究日誌保留錯誤形成原因與新證據索引。
- 下一輪只從矩陣的 `下一閘門` 開工，不從歷史 `[x]`、聊天摘要或完成百分比推導範圍。

## MOO2 觸發本規則的實例

2026-08-12 的《銀河霸主 II》稽核顯示：專案可玩且有大量具名原版函式，但議會票數／排程、
戰略轟炸、外交與 AI 等仍有已證實的 remake 模型差異。這個案例只用來說明方法失敗形狀；
各專案的公式與位址必須留在自己的受版控證據文件，不複製進通用知識庫。
