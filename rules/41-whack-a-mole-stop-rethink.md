# 打地鼠停損：特例越修越多 = 停下重想架構

> 與 `40-learning-loop` 互補。40 講「每輪更新假設」；本條講**何時該放棄整條路線、退回第一性原理**——因為 learning loop 也可能在一條錯的路上越走越深。

## 核心

**症狀（whack-a-mole smell）**：每修好一個特例，就冒出一個新特例；build-test / 嘗試循環越滾越多，解法越補越長、分支越加越雜，卻始終差臨門一腳。這不是「快好了」，是**路線本身錯了**的訊號。

**對策**：停手，回到第一性原理問一句——**「這任務的本質目標是什麼？」** 然後找那條繞過所有特例的路。通常存在，而且往往是「**用系統既有的機制**」而非自己重造（見 retro 案例：略過驗證不是逐題答對，而是用引擎既有的 restore/除錯換場機制直接跳到門後房間，一次解決全部題型）。

## 該停手的升級信號（命中任一就停下重想，別再補特例）

1. **特例增生**：修 A 冒出 B、修 B 冒出 C，且彼此不共用解法。
2. **循環暴增**：同一子問題 build-test 超過 ~5–8 輪還在「再差一點」。
3. **使用者表示意外**：使用者問「有這麼難嗎 / 不是很簡單嗎」——這是**最強的退一步信號**，代表對方直覺有更短的路，別辯解，先重想。
4. **成本 vs 價值失衡**：在一個 nice-to-have 上燒掉與其價值不成比例的時間/token（高階模型尤其貴，見 `45-model-cost`）。
5. **繞過 vs 正面對決**：發現自己在「模擬/複製」系統的複雜行為（模擬玩家作答、重造引擎流程）——先問「能不能不要模擬，直接用系統自己的入口？」

## 停下後做什麼

1. 一句話寫出**本質目標**（去掉所有已陷入的實作細節）。
2. 列 2–3 條**完全不同**的路線（不是現有路線的微調），至少一條是「用既有機制/繞過」。
3. 若仍不確定，**回報使用者**現況 + 候選路線，讓對方一句話點方向——比獨自硬幹省得多。

> [HARD] 撞牆是資訊，不是要你更用力。同一障礙第 N 次時，換的應是**方法**，不是力氣。「再試一次同樣的做法」不算換方法。
