# 本地化的顯示與語意隔離

翻譯只能改變玩家看到的內容。條件比較、資源查找、存檔名稱、腳本鍵值、序列化資料
與協定欄位必須使用穩定的原始識別值。共用字串函式若同時服務顯示與語意用途，應在
API 上拆開或提供明確 gate；不可在共用出口無條件翻譯。

## 已證實案例

ScummVM AGOS 的 Elvira 1 曾因 `getStringPtrByID()` 無條件翻譯，使
`oe1_isCalled()` 比較的 `The soldier`／`the soldier` 變成「那名士兵」／「士兵」。
敵人分類失敗後戰鬥圖片變數保持 0，最後誤載 `002.VGA`。玩家繁中／英文 A/B log、
相同遊戲資料雜湊與原始碼呼叫鏈共同證實這條因果關係。

## 工作流程

1. 盤點翻譯掛勾的所有呼叫者，分類顯示、比較、查找、識別、序列化與外部介面。
2. 顯示路徑可預設翻譯；其他用途明確取得原始值。
3. 用同資料、同操作做原文／譯文差分，確認差異只存在顯示層。
4. 以原文相等但合理譯文不相等的案例測試語意隔離。
5. 走完真實受影響流程，不以啟動成功、畫面正常或短時間未當機代替驗收。

禁止用統一個別譯文的方式迎合比較。應修 API 責任邊界，避免契約藏進翻譯內容。
