# Verification Fidelity — 案例庫（按需讀）

四個「我說修好了 → 真實環境又壞」的完整還原。每則:**症狀 → 我當初怎麼錯誤地『驗過』 → 真正的根因 → 正確的驗法**。出處都是 freesynd-cht(Bullfrog Syndicate 的繁中化，開源引擎，無客戶機密)，但教訓跨專案通用。

---

## 1. 環境對嗎 — Wine 預設碼頁 ≠ 真實 CP950

- **症狀**：Windows 使用者把遊戲放在**中文資料夾**下，一開就閃退。
- **我怎麼錯誤地驗過**：在 Wine 下跑過、沒閃退 → 回報「已在 Wine 驗證」。
- **根因**：預設 Wine 的 ANSI 碼頁是 **UTF-8**，所以 `fopen(utf8_path)` 剛好讀得到；但真實繁中 Windows 的 ACP 是 **950 / Big5**，同一條 UTF-8 路徑被當 Big5 解 → 檔案開不到 → crash。預設 Wine 是個**比真實環境寬鬆的替身**。
- **正確的驗法**：強制把 Wine 碼頁設成真實值再重現：
  ```
  wine reg add "HKLM\System\CurrentControlSet\Control\Nls\CodePage" /v ACP /d 950 /f
  ```
  重現後才動手修(改用 UTF-8 manifest / 寬字 API),修完再用同一個 ACP=950 環境驗。
- **通則**：找出觸發 bug 的**精確條件**(locale / 碼頁 / OS / 路徑 / 時序),必要時用 registry / env / fixture **強制**重現那個條件。重現不出來就**明說並降低信心**,不要拿替身的「過」當「驗過」。

## 2. artifact 新嗎 — stale binary 渲染了「修正前」截圖

- **症狀**：修了 squad-select 版面後,GitHub README 上的 `squad-select.png` 還是舊的錯位畫面。使用者:「github repo readme 展示的 squad-select 沒有更正。」
- **我怎麼錯誤地驗過**：`git stash` 改別的東西 → build → `git stash pop` 拿回版面修正 → **沒重 build** 就用當前 binary 渲染截圖 → 渲到的是「修正前」的二進位。
- **根因**：量測用的 artifact 不是「含這次修正」的那一個。
- **正確的驗法**：任何「改碼 → 量測/截圖/出貨」之間,**強制重建**;懷疑就核對 binary 的 mtime 是否晚於原始碼改動時間。`git stash` pop 之後**一律重 build**。
- **通則**:stale artifact(舊 binary / 舊快取 / 舊 image)會給你一個與當前程式碼無關的「結果」。先重建再量測。

## 3. 真的互動了嗎 — HD `mapY` 了 render 卻沒改 hit-test

- **症狀**：HD 版整備畫面看得到武器圖示,但**點不動、不能賣**。(這是我自己引入的 regression。)
- **我怎麼錯誤地驗過**：截圖看起來版面對齊了 → 當成修好。
- **根因**：我把庫存圖示的**渲染**座標 HD-`mapY()` 了,卻把 `handleMouseDown` 的**命中判定**留在 raw 座標 → 看得到的位置和點得到的位置分離。最痛的是:我自己的 `docs/ENGINE-NOTES.md` 就寫著「render 位置和 hit-test 都要 map」——**我寫了規則又違反它**。
- **正確的驗法**:把 render-座標 和 hit-test-座標 當成**同一個改動**,一起改;UI 改完一定**真的驅動一次點擊**,確認動作有觸發(不是只截圖)。
- **通則**:只要動了用來「畫」的座標(scale / offset / map),它的點擊判定要拿到**相同變換**;驗證靠互動,不靠看。寫下 gotcha ≠ 內化 gotcha——拿自己的 diff 去對自己的踩雷清單。

## 4. 戳破隱藏假設了嗎 — CJK 折行無空格 → 無窮迴圈

- **症狀**：完成某關後進到下一關、按「簡報」,卡在空白灰畫面(tester 回報)。50 關裡 **28 關**會卡。
- **我怎麼錯誤地驗過**：寫了一個「結構驗證器」數簡報檔的 `|` 分隔段數,全綠 → 當成可上。
- **根因**:兩層假設被翻譯戳破——(a) 引擎的 word-wrap **只在空格斷行**,CJK 沒有空格,整行變成一個「超寬的單字」永遠塞不進去 → `read_next_word` 不前進 → 外層 `update_briefing_text` 無窮迴圈;(b) 我的驗證器只看結構,**沒模擬真實 470px 折行寬度**,所以放行了會在 runtime 卡死的 28 關。英文版完全看不出來。
- **正確的驗法**:換語言/平台/資料規模時,**稽核引擎程式碼的隱藏假設**,不是只換字串。針對 CJK 去 grep:word-wrap/斷行邏輯(只認空格?)、固定文字寬度/欄位預算 vs 真實字元寬、narrow path I/O(碼頁)、逐 byte 走字串會不會切斷多 byte 字元。驗證器要**模擬真實 runtime**(這裡是實際字體寬度 + 折行迴圈),不能只做結構檢查。修**引擎**,不是只修資料。
- **通則**:在地化 = 把為「原語言假設」寫的程式碼放到結構不同的輸入下跑;驗證要涵蓋這些結構性差異(無空格 / 寬字 / 非 ASCII 碼頁 / 多 byte 邊界)。

## 一句話收束

builds 綠 + 我自己腳本化的 QA 通過 **≠** 對玩家可用。這四則的共同點:我都用了一個**比真實情境寬鬆的替身**(預設 Wine / stale binary / 截圖 / 結構驗證器)當作「驗過」。最可靠的訊號永遠是:**在真環境、用新 build、真的走一遍使用者旅程**。
