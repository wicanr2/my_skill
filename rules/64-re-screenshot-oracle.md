# RE 撞牆改用「截圖 oracle 反推資料位置」(逆向工程第三條路)

> 觸發:逆向工程找某筆資料(tileset / 圖 / 表 / 字庫 / 音色)**撞牆**——
> 動態 dump 走不通(卡對話框、注入不穩、要進特定遊戲狀態才填 buffer),
> 或繼續反組譯追資料流(誰填這塊 memory、JSL/跳表 dispatch)成本爆高時。
> 與 `62-static-provenance-trace`(靜態反追溯源)、`60`(先建可驗證 pass/fail 訊號)同源互補。

## 核心洞見(第一性原理)

找一筆未知位置的資料,有三條路,別只想到前兩條:

1. **動態**:跑起來,在記憶體 dump 那塊 buffer。← 常卡(對話框、模擬器注入、要進特定狀態)。
2. **靜態追資料流**:反組譯找「誰寫這塊 memory」「指標從哪來」。← JSL/跨 bank/跳表 dispatch 時成本爆高、易迷路。
3. **★ 反推**:**已知的解碼器 + 已知的輸出 = 反推未知的資料位置**。

第三條路最常被忽略,卻常最快。前提通常已經到手:
- 你**已經破解了解碼/壓縮格式**(LZSS、RLE、bitplane、charset…)——這是把任何候選位元組變成像素/結構的能力。
- 你**已經有「正確輸出」當 ground truth**——實機截圖、原版錄影、已知正解的另一版本、文件裡的範例。

那就**別追資料怎麼來,直接拿解碼器掃所有候選位置,用已知輸出當 oracle 比中哪一塊**。

## 操作流程

1. **備 oracle**:從實機截圖 / 原版錄影 / 另一平台版本,切出**幾個你能肉眼認得的已知單元**(grass、water、player、某個字…),對齊目標單元尺寸(如 16×16)。
2. **窮舉解壓 + 滑窗**:把每個候選 resource / 檔案 / 區段用**已破解的解碼器**解開,以單元大小(如 128 bytes = 16×16 4bpp)為步長**滑窗**切塊。
3. **結構比對(關鍵:要 palette 無關)**:
   - 截圖的 RGB 與目標的 palette index **往往不是同一套**(顏色被縮放、gamma、非整數倍)→ 直接比顏色會全 miss。
   - 解法:把每塊像素用**「首次出現順序」重新編號**成 canonical pattern(第一個出現的色→0、第二個→1…),**比圖樣不比顏色**。形狀對上,相似度就 ≈1.00。
4. **命中即定位**:相似度 ~1.0 的那塊 offset 就是資料起點。往前往後推算同類單元的範圍(如「命中 grass @11392 → tile 88,推得 88–135 共 48 個」)。
5. **反推 palette**:位置定了,palette 還能再用同一批截圖反推——把目標 tile 的每個 index 對到截圖對應像素的 RGB,**多數決**填出 index→RGB 表。
6. **驗證**:組出資產 → game tester 進對應畫面渲染,肉眼確認(見 `retro-game-playtest`)。

## 為什麼有效(別跳過這層理解)

- 解碼器是「位元組 → 結構」的**確定性函數**;截圖是這函數在某輸入下的**已知像**。在候選空間裡找「解碼後 ≈ 已知像」的輸入,是一個有 oracle 的搜尋問題——比「無 oracle 地反推控制流」好做太多。
- palette 無關的結構比對,把「顏色不一致」這個最常見的假陰性源頭消掉,留下純拓樸資訊,跨版本/跨截圖都穩。

## 落地案例

**u1-cht Apple IIgs(2026-06)**:overworld tileset 找不到——`$4c00` tile buffer 只在進 overworld 才填,
卡 GS/OS 滑鼠對話框(動態走不通),JSL/跳表 dispatch 讓靜態追資料流也卡。
改走第三條路:已破解 LZSS + hg101 實機截圖,結構比對命中 **id08 tile 88–135 = 完整 48-tile overworld tileset**
(@11392 grass 1.00 / @11520 water 1.00 / @11776 castle 0.98),再反推 palette。
→ 全 52 槽變 100% 真實 IIgs 像素,EGA fallback 全除。詳見該 repo `docs/re/apple-iigs-reverse-engineering.md` Step 12。

## 反模式

- ❌ 動態 dump 卡住 → 一直硬鑽模擬器注入 / 對話框 自動化(投報率低)。
- ❌ 顏色直接比 RGB → 因 palette 不同倍數全 miss,誤判「截圖裡沒有」。
- ❌ 已經破了解碼器,卻仍只想著「繼續反組譯找填 buffer 的碼」——忘了解碼器本身就是搜尋武器。
- ❌ 找到位置就收工,不反推 palette、不進遊戲渲染驗證。
